## Business problem, and the cost of being wrong

For this project, I wanted to use computer vision for something related to gaming, since it is a domain I understand well. The system is designed to support Valorant VOD and replay analysis.

The main decision is whether a gameplay frame contains a visible enemy body and therefore should be considered relevant for review. Instead of a coach or analyst manually going through every sampled frame of a VOD, the model can automatically skip low-confidence frames, flag high-confidence frames, and send uncertain cases to a person.

The positive business class is `enemyBody`.

I treated a false negative as more expensive than a false positive. A false negative means that there actually is an enemy visible but the system misses the frame. This can cause an important combat or positioning situation to be skipped completely and may require the analyst to search through the VOD manually later.

A false positive means that the system flags a frame even though there is no enemy body. This is still a mistake, but the main consequence is only that the analyst wastes some time checking an unnecessary frame.

For the cost model, I used an analyst cost of €48 per hour.

- False positive: approximately 15 seconds of unnecessary review = **€0.20**
- False negative: approximately 120 seconds of additional manual searching = **€1.60**
- Human review of an uncertain frame: approximately 15 seconds = **€0.20**

This means a false negative is treated as eight times more expensive than a false positive. The exact numbers are assumptions rather than values provided by the dataset, but the important idea is that missing a useful combat event is more costly for this use case than reviewing one unnecessary frame.

## Finetuning and baselines

I used **YOLO11n** for object detection.

I selected the nano version because the dataset is relatively small and the model is lightweight enough to train and deploy efficiently while still using pretrained YOLO features.

The final model was trained for **50 epochs** using an image size of 640 and batch size of 16. I trained the model locally using an **NVIDIA GeForce RTX 5070 Ti Laptop GPU**.

The training pipeline compares three approaches on the same held-out test split:

1. Finetuned YOLO11n trained on the Valorant dataset.
2. Pretrained YOLO11n using COCO weights with no Valorant finetuning.
3. A trivial baseline that predicts nothing.

For the COCO zero-shot comparison, the pretrained COCO `person` class is mapped to `enemyBody`, because COCO does not contain Valorant-specific `enemyBody` or `enemyHead` classes. There is no direct COCO equivalent for `enemyHead`.

The exact zero-shot baseline output is saved in `artifacts/coco_zero_shot.json`, while the trivial baseline is saved in `artifacts/trivial_baseline.json`.

The trivial predict-nothing baseline has zero recall because it never produces a positive detection.

The finetuned model achieved the following overall results on the held-out test split:

| Metric | Result |
|---|---:|
| Precision | 0.770 |
| Recall | 0.792 |
| mAP50 | 0.790 |
| mAP50-95 | 0.297 |

These results show that finetuning allows YOLO to learn useful Valorant-specific visual information instead of relying only on generic pretrained COCO classes.

## Cost matrix and operating point

The model outputs a confidence score for its detections. I swept the confidence threshold from 0.01 to 0.99 rather than selecting 0.50 automatically.

For the model-only decision, the cost function was:

`Total cost = FP × €0.20 + FN × €1.60`

The observed positive base rate in the held-out test set was **0.843**, meaning approximately 84.3% of the test images contained at least one `enemyBody`.

Because the positive class is very common and false negatives are much more expensive than false positives, the cost model strongly prefers a low confidence threshold.

The minimum-cost model-only threshold was:

**0.01**

This initially looks unusually low, but it follows directly from the cost assumptions. The system is encouraged to make aggressive positive predictions because incorrectly flagging a frame costs much less than completely missing an enemy frame.

The cost-against-threshold curve in the dashboard shows that expected cost increases substantially as the threshold becomes more conservative.

The most important assumption affecting this result is the false-negative cost. If missing an enemy were much less expensive than assumed, the optimal threshold would move upward.

## What a person still has to check

Instead of using only one confidence threshold, I also implemented a three-outcome system:

- Confidence below **0.05** → automatically pass/skip the frame
- Confidence from **0.05 to 0.10** → send the frame to human review
- Confidence of **0.10 or above** → automatically flag the frame

The cost optimization selected an assisted review band of:

**0.05 – 0.10**

At this operating point, the held-out test results were:

- True positives: **43**
- False positives: **3**
- True negatives: **5**
- False negatives: **0**
- Share sent to human review: **2.0%**
- Expected cost per 1,000 cases: **€15.69**

Assuming 2,000 sampled frames per day, approximately **39.2 frames per day** would be sent to human review.

At 15 seconds per review, this represents approximately **0.16 hours of review work per day**, which is a relatively small workload.

This is the main advantage of the assisted system. It does not require a person to check every frame, while uncertain cases can still be escalated instead of forcing the model to make every decision alone.

The zero false negatives on this test set should not be interpreted as proof that the deployed system would never miss an enemy. The test set contains only 51 images, so the result is based on a relatively small sample.

Compared with the alternatives:

**Doing nothing** would mean analysts continue manually searching through VOD footage.

**Reviewing everything manually** would provide more human control but would require substantially more analyst time.

**Model-only automation** reduces human workload but creates more risk from uncertain predictions.

The assisted approach provides a middle ground by automatically handling confident cases and sending only a small uncertain group to a person.

## Limitations & next steps

The first limitation is the small test split. With only 51 images, the reported performance and optimal thresholds may change significantly if a larger test set is used.

The second limitation is that the dataset may not represent every possible production situation. Valorant contains different maps, agents, weapons, abilities, resolutions, visual settings and recording qualities. A model trained on a limited dataset may perform worse on gameplay that looks different from the training images.

Another limitation is that the detector only understands visual objects. Detecting an enemy does not automatically mean that a frame is tactically important. A real coaching system would also need information such as player position, map location, round state and what happens before and after the frame.

The base rate is also estimated using the test dataset rather than a real production stream. The 84.3% positive rate is very high and may not represent a system that samples frames from complete matches. A different production base rate could change the cost-minimizing threshold.

Finally, the business costs are based on assumed analyst time. A real organization should measure the actual review time and cost before choosing a production threshold.

With more time, I would evaluate the system on a larger and more varied set of Valorant recordings, measure a realistic production base rate, and recalculate the threshold and human-review band using actual analyst workload data.
